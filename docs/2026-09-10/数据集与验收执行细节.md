### 2.3 “优雅”如何评审

每仓库按目录和文件长度抽 10 个生产源码文件，每文件抽 3 个候选区域，总计约 540 个区域。短文件不足则全量检查，记录不足，不重复凑数。

用五项 0–2 分评审：同一逻辑步骤紧凑、阶段之间有分段、注释与对象归属清楚、纵向密度适中、同项目局部一致性。建议均分至少 8/10 才进入主要训练来源；争议区域不作为强标签。

尽量让两位评审者独立评分；若只有一位评审者，可间隔复评，但报告中不能声称具有双人一致性。评分量表先用少量开发样本校准。

筛选失败时调整到该仓库已评审的子目录，不以星标数替代质量；仍不足则把来源标为不合格，提出替换理由再修订 18 项清单。

## 三、Edges：采集、清洗和集合约束

### 3.1 下载与解压执行规格

这里的“安装包”应落实为 GitHub 源码归档，不是 npm wheel jar 或编译好的发布包。无需安装、构建或运行第三方仓库。

1. 获取每个仓库默认分支的完整 SHA，记录采集时间和仓库规范 URL。
2. 构造 `https://codeload.github.com/<owner>/<repo>/tar.gz/<完整SHA>`，不使用漂移的 main/master 作为最终下载标识。
3. 先写临时归档，检查 HTTP 状态、归档格式、实际大小，再计算 SHA-256、原子移动到归档目录。
4. 解压前检查成员路径，拒绝绝对路径、`..` 穿越、越界符号链接和不支持的特殊文件；设置总大小与文件数量上限。
5. 解压到独立的 `<owner>/<repo>/<sha>/` 下；原始文件不可覆盖或格式化。
6. 每仓库最多重试 3 次，失败写入记录；只复用 SHA 和校验和匹配的归档。子模块/LFS 缺失明确记录，不当成完整源码。
7. 下载完核对 18 个来源状态与来源锁文件；固定提交提供版本标识，归档 SHA-256 提供此次取得字节的校验记录。

来源记录字段：repository、commit、archive_url、archive_sha256、downloaded_at、license_files、selected_paths、excluded_paths、role、status。文件记录追加 source_path、source_sha256、language、encoding、split_group、rejection_reason。

### 3.3 清洗管线

1. 仅纳入已评审路径中的目标扩展名；TSX/JSX 必须用对应语法识别，不能按纯 TS/JS 标签混用。首轮训练以六种纯语言源码为主。
2. 排除 vendor、third_party、node_modules、dist、build、快照、fixture、生成文件、压缩文件及文档嵌入代码。目录名只是线索，结合文件头和来源清单判定。
3. 校验 UTF-8；保留 BOM 和 LF/CRLF 信息。非法编码先隔离，不静默转码。极小文件和超大文件分桶，不能因模型窗口限制截断字符串。
4. 做原始哈希去重，再用保留字符串/注释内容、忽略可编辑布局的结构指纹做近重复候选匹配。通过 token 片段相似度复核；初始相似阈值可设 0.85，仅在开发样本校准。
5. 同源复制、版本变体、同步/异步近似实现、重载模板归入同一重复组。组内保留代表或降权，整个组只能位于一个集合。
6. 解析完整文件，提取注释和字面量保护区、兄弟语句边界、原始空白布局和字节映射。有错误节点的区域不生成可写训练样本。
7. 对 A 生成标签：相邻可编辑非空行之间有几个空白行。超过 2 个的异常区域先隔离评审，不直接截为 2 从而伪造标签。
8. 生成受控输入：移除/增加安全空白行；不改变缩进、不拼接非空行，不改多行字面量。不以正则全文件删除 `\n`。
9. 按完整文件/完整语法区域构建窗口。上下文来自同一集合，跨窗口候选只保留一个评估身份；窗口边缘补足上下文或屏蔽，不能重复算分。
10. 记录分语言文件数、独立重复组数、候选数、标签比例、行长、嵌套深度、丢弃原因和来源占比。所有清洗阶段都可从固定输入重跑。

TypeScript 的源码结构搜索使用 ast-grep；不以文本正则定位函数或语句。文件名枚举和元数据读取不承担语法判断。

### 3.4 训练/验证/测试隔离

六个整仓测试来源：Zod、Koa、HTTPX、Gson、Axum、ZLS。其内容不参与词表统计、特征标准化、类别权重估算、量化校准、模型选择和阈值调整。

其余 12 个仓库按完整文件和重复组划分，文件哈希约 85% 训练、15% 验证，不拆散文件。验证集不是完全跨仓库；跨项目能力由六个独立来源测量，跨语言能力由额外六种完全不参与训练的语言测量。

跨测试仓库与训练仓库检测到重复时，优先删除训练侧重复成员，保留测试组隔离；对疑似共享上游来源的样本人工复核。只允许依据来源与重复关系清理测试，不依据模型难度删除它们。

初始规模预算为每语言约 5万–15万个边界，实际数量按来源记录，不补重复数据凑数。实现采用语言均衡抽样，个人风格训练中使用 50% 个人参考和 50% 跨语言回放；尚未实现严格的单仓 60% 配额，这项来源偏差应在后续数据扩充中处理。

20 组测试均从隔离的真实仓库来源产生，不能从训练集拿片段再改空白冒充测试。另有独立的开发期定界符保护验证。Ruby 的首次构建暴露识别歧义并参与了保护逻辑迭代；报告明确这一影响，不称为完全未触碰的黑箱评测。

### 4.2 不把“原作者空行”当唯一答案

当前有原作者布局恢复指标和个人参考验证指标；独立人工审美盲评仍待完成。未来可保留多个合理答案，不强行把审美分歧合并成唯一真值。

针对几乎没有空行的输入，“全不改”可能很准确，因此不能单看 accuracy。固定原始/扰动比例和采样分母，统计每个独立片段的修改覆盖率。

盲评隐藏仓库名、模型名和原始答案，打乱展示顺序，分别给出更易读/相当/更差的判断；这项工作可用静态 diff，不需要浏览器 UI 自动化。
