# 训练与测试结果

## Intent：本次交付目标

交付可运行的第一版 gpu-code-spacer：Zig 主程序、共享小模型、通用 Tokenizer、默认 zgpu 硬件 GPU、不可用时 CPU 回退，以及内嵌模型的单文件程序。

审美目标是“代码如诗，不仅好读，也要好看”。本版实现已有代码行之间的空行分段，尚未实现长行折行或重新缩进。

## Data：已完成的实证

### 模型与数据

- 模型：128 个输入特征、64 个隐藏单元、3 类空行标签，共 **8,451 个参数**。
- 内嵌权重：**33,860 字节**，FP32，带格式、维度、特征版本和 SHA-256 校验。
- 特征版本：3。模型输入没有语言名、扩展名、仓库名、原始空行数或绝对行号。
- 来源：18 个初始项目、6 个只评估的未见语言项目、2 个个人风格来源。
- 个人参考：用户确认手写的 if，以及从 polywise 中筛选的 12 个局部范围。后者作者身份未知。
- 训练：3 个随机种子分别进行基础训练及个人风格训练。个人风格阶段混合 50% 风格样本与 50% 跨语言回放。
- 选模：只依据开发和个人风格验证集，选定 seed 2026 的风格模型，默认置信度 0.70。

完整数据规模与拒绝原因保存在 `data/processed/summary.json` 和 `files.json`；训练记录保存在 `models/training.json`，来源提交保存在 `config/*sources.lock.json`。

### 个人风格校准

在 4,906 个隔离的个人参考验证边界上，默认阈值的结果为：

| 指标 | 结果 |
| --- | ---: |
| 新增空行 precision | 96.23% |
| 新增空行 recall | 79.64% |
| 布局分类 accuracy | 93.09% |
| 布局 macro-F1 | 0.9121 |

这里的 precision/recall 针对移除安全空行后的恢复任务，参考答案来自原作者布局。这一验证集用于校准，不应当描述成独立最终测试，也不是“美观程度”的客观分数。

### GPU 与单文件验证

实测环境：Apple M5、32 GiB、macOS，Zig 0.16.0。

| 检查 | 结果 |
| --- | --- |
| 实际后端 | zgpu / Dawn → Metal |
| GPU/CPU 数值对照 | 1,025 个输入，最大绝对误差约 3.81e-6 |
| 分类一致性 | 1,025 / 1,025 |
| 对照运行批次 | 5 GPU，0 CPU |
| 无 GPU 构建的回退 | 0 GPU，5 CPU，误差 0 |
| 最终 20 组测试推理 | 5,561 GPU 批次，0 CPU |
| 独立目录运行 | 只复制程序、清空进程环境后，仍选择 Metal 并执行 GPU 推理 |
| 动态依赖 | 仅 macOS 自带系统库与 framework，无 Dawn/模型旁置文件 |

CPU 回退验证使用了不编入 GPU 后端的构建，属于不可用后端的模拟，不等同于物理移除 GPU。

完整程序约 9.8 MiB，主要增量来自静态 Dawn 与 WGSL 编译基础设施；不能将这个体积与约 33 KiB 的模型权重混为一谈。

### 20 组测试

每组 30 个不重复评分区域，共 **600 个**。区域可以共享完整文件上下文，不应当称为 600 个独立项目或统计独立的文件。

| 分组 | 覆盖 |
| --- | --- |
| 01–06 | TS、JS、Python、Java、Rust、Zig 的独立项目 |
| 07–12 | 未训练的 Go、C++、C#、Ruby、Kotlin、Swift |
| 13–16 | 注释附近、嵌套块、长表达式、顶层分段 |
| 17–20 | 保护区域、CRLF、幂等、受控空行扰动 |

- 600 个区域完成非空行字节保持与幂等检查。
- 其中 309 个案例有离线语法树对照，通过；291 个没有对应语法检查器，单独标记为未验证。
- 11 个案例由于词法不确定而保留原文（JS 7 个、Python 4 个），没有隐藏这部分放弃。
- 每组抽取一个案例实际执行编译后的 CLI，并检查 stdout 与 `--write` 结果，共 20 次二进制集成检查。
- 通用保护验证另外覆盖 20 种定界符形态、60 种布局变体，以及编码、数据尾部和运算符歧义检查。

### 跨语言布局一致性

下表是固定模型与原作者布局的一致性，**不是用户审美的直接评分，也不是完整工具的语义正确率**。macro-F1 的类别集合按各语言参考标签中出现的类别固定。

| 语言 | 是否参与基础训练 | 模型 F1 | 固定规则 F1 |
| --- | --- | ---: | ---: |
| TypeScript | 是 | 0.7955 | 0.8033 |
| JavaScript | 是 | 0.6686 | 0.7324 |
| Python | 是 | 0.8078 | 0.3603 |
| Java | 是 | 0.8399 | 0.8057 |
| Rust | 是 | 0.6026 | 0.5617 |
| Zig | 是 | 0.8088 | 0.7275 |
| Go | 否 | 0.8032 | 0.8332 |
| C++ | 否 | 0.7335 | 0.7468 |
| C# | 否 | 0.4776 | 0.5060 |
| Ruby | 否 | 0.6803 | 0.6321 |
| Kotlin | 否 | 0.8020 | 0.7887 |
| Swift | 否 | 0.8364 | 0.8673 |

已见语言的新项目宏平均：模型 **0.7539**，规则 **0.6651**。

未见语言宏平均：模型 **0.7222**，规则 **0.7290**。这意味着已有迁移能力，但尚未证明模型在未知语言上普遍优于规则；C# 是明显薄弱项。

额外的留一语言实验将 Zig 从训练与验证选模中完全排除，再在 ZLS 的 26,889 个边界上评估，得到 macro-F1 **0.7973**。该实验通过 106 个 GPU 批次完成。

### 性能

600 个案例的整文件引擎调用，稳态 p50 为 **4.24 ms**，p95 为 **24.39 ms**。

该计时包含 Tokenizer、特征、推理与字节检查，不包含磁盘读取、进程启动和首次 GPU 初始化。它不是冷启动性能承诺，也不是所有文件大小的固定延迟。

另对 15,526 字节的 ZLS 源文件启动 10 个独立 CLI 进程，系统计时均显示约 0.02 s（显示精度有限）；实际执行 2 个 GPU 批次、0 个 CPU 批次。系统和着色器缓存未清空，因此不能视为首次安装后的完全冷启动。原始记录见 `runs/cli-process-timing.txt`。

## Edges：边界与自我审查

1. **这仍是实验版。** 未见语言平均分尚未超过规则基线，不能宣传成“90 多种语言都精确排版”。
2. 个人风格数据主要来自 TypeScript。对其他语言更疏朗的输出，需要按审美评价，不能只靠复刻紧凑仓库的原样布局。
3. 通用保护不是完整语法解析器。309 个语法对照通过不能推导 291 个未验证案例或任意未知语言都语义不变。
4. Ruby 的初次测试构建暴露了定界符与运算符歧义；修复公共识别逻辑后重跑。Ruby 未用于梯度或阈值选择，但其保护逻辑受到了迭代测试反馈，不能描述为完全未接触的黑箱评测。
5. 24 个基础源码片段与 12 个 polywise 片段进行了模型辅助阅读，尚未完成计划中更大规模的独立人工盲评。
6. 未实现新的行内断行、GPU 训练或其他平台实机验证。当前交付的核心功能是空行分段和默认 GPU 推理。

## Answer：交付物

- `zig-out/bin/gpu-code-spacer`：内嵌模型与 WGSL 的 macOS 程序。
- `models/`：可复现权重、默认阈值、模型元数据和所选训练记录。
- `data/evaluation/`：20 组 JSONL 测试，含输入、原始参考和预测片段，以及完整报告。
- `runs/gpu-verification.json`、`runs/cpu-fallback-verification.json`、`runs/transfer-zig.json`：后端和迁移实验记录。
- `README.md`：构建、使用和复现步骤。
- [样例对照](./样例对照.md)：可以直接阅读的输入、模型输出和原作者参考。

后续改进应优先提升未知语言的边界表示与语义分段，并建立独立的跨语言审美标注；不通过调测试集阈值或为特定文件添加规则来抬高分数。
