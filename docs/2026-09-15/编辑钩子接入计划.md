# 编辑钩子接入计划

## Intent：最终目标

通过 Codex PostToolUse，在标准补丁编辑完成后批量调用 gcs 美化本次修改的代码文件。

## Data：可用证据

- 本机 Codex CLI 0.153.4，hooks 为 stable 且已启用。
- 官方文档支持 PostToolUse 匹配 apply_patch；其输入包含 tool_input.command 和 tool_response。
- 用户级 hooks.json 不存在，没有同级内联 hooks 配置。
- gcs 支持一次传入多个文件并共享模型实例。

## Edges：边界与限制

- 使用用户级配置；仅处理成功补丁中的新增、修改和移动后代码文件。
- 删除项、非代码文件不处理。不依赖 Git，不遍历整个项目。
- 不覆盖 Bash/Python 等任意命令写文件；这些操作没有统一的修改文件列表。
- 不生成测试用例，不调用浏览器 UI。
- 官方要求非托管 hook 首次使用前由用户在 /hooks 审核并信任，配置落盘不等于已经启用执行。

## Answer：交付与成功标准

- 仓库保存小型 Python 适配脚本；用户级 hooks.json 引用该脚本和已有 gcs 可执行文件。
- 编译检查 Python 语法、核对 JSON 配置、使用现有评估文件副本核查实际格式化。
- 记录实现限制及最后需要用户执行的信任步骤。
