# 移除旧后端执行记录

## Intent：最终目标

按用户后续要求移除 zgpu，使训练与产品推理统一使用 ggml。上一轮仅迁移训练的边界已被本轮取代。

## Data：可用证据与执行结果

### 代码与构建

- 删除 `src/gpu.zig` 与 `src/model.wgsl`。
- 清空 `build.zig.zon` 的 zgpu、system_sdk 和五个 Dawn 平台包依赖。
- 删除 `build.zig` 中的 zgpu 目标检查、导入、zdawn 链接与旧平台路径配置。
- 新增 `src/ggml.zig`，集中管理 ggml 设备、权重转置和前向图；训练封装引用该模块，不再维护重复前向实现。
- `src/inference.zig` 使用同一前向图执行产品 GPU 和 CPU 推理。GPU 初始化/执行失败时释放会话，重建 ggml CPU 会话；CPU 失败正常返回错误，没有额外的手写推理兜底。
- Runner 初始化改为可返回错误；四个调用者同步处理，避免隐藏 CPU 资源初始化失败。
- `-Dgpu=false` 保留，语义为只使用 ggml CPU 推理；静态库集合不变，训练 `--backend` 独立控制。
- `tools/verify_gpu.zig` 改用固定种子的合成权重，保留原有 1,025 输入、尾批、误差阈值、分类一致性和批次计数检查。
- 新增 `-Dmodel-config`，与原 `-Dmodel` 一起支持绝对路径，供临时匹配权重和配置使用。

### 静态分发

ggml 引导固定以下选项：

```text
BUILD_SHARED_LIBS=OFF
GGML_BACKEND_DL=OFF
GGML_METAL_EMBED_LIBRARY=ON
GGML_NATIVE=OFF
GGML_OPENMP=OFF
GGML_BLAS=OFF
```

Zig 明确链接 `.a` 文件，避免安装目录残留的旧动态库影响链接选择。macOS 使用 ggml、ggml-cpu、ggml-metal、ggml-base 和系统 Foundation、Metal、MetalKit、Accelerate 框架，C/C++ 运行库由 Zig 链接。

`otool -L` 确认应用只依赖系统框架和运行库，没有 ggml/Dawn 动态库或仓库路径依赖。关闭宿主专用指令优化不等于已经验证跨平台或旧版 macOS 兼容性。

### Metal 精度问题及修正

初次保留二维大批量矩阵乘法时，1,025 个合成输入的最大误差为 `0.00210905`，超过既有阈值 `0.0001`，尽管分类全部一致。

固定 ggml 源码中，Metal 大矩阵 `kernel_mul_mm_f32_f32` 的内部操作数类型包含 `half`；仅声明 F32 张量不足以避免精度降低。该版本 Metal 大矩阵选择逻辑也没有依据 `GGML_PREC_F32` 切换计算精度。

最终共享图将输入从 `[features, batch]` 表示为 `[features, 1, batch]`：每个样本是独立矩阵向量乘法，权重沿 batch 维广播，两层计算后恢复 `[outputs, batch]`。这保留完整 F32 矩阵向量路径、原模型数学和样本排列，适用于所有样本，而不是对某条验证输入做特殊处理。

没有放宽误差阈值，没有修改上游 ggml，没有新增自定义 GPU 内核。此布局选择优先保证精度，不能据此宣称训练或推理比旧实现更快。

上游依据：[Metal 大矩阵类型](https://github.com/ggml-org/ggml/blob/7840aaba1989c6deeefede1d77d5aaf8f52b947e/src/ggml-metal/kernels/mul_mm.metal)、[矩阵路径选择](https://github.com/ggml-org/ggml/blob/7840aaba1989c6deeefede1d77d5aaf8f52b947e/src/ggml-metal/ggml-metal-common.cpp)。

### 冻结模型的既有版本不匹配

在独立运行默认应用时确认：`models/config.zig` 中 `feature_version=5`，当前源码 `src/features.zig` 为 v6，应用按原保护逻辑返回 `FeatureVersionMismatch`。

这与计算后端无关，不能通过删除版本校验或强改配置数字解决。本轮没有改冻结模型、配置或特征。完整应用验证使用临时 v6 权重以及临时 v6 配置，并以临时 `--prefix` 安装，避免覆盖正式模型资产。

可复现形式：

```sh
zig build -Doptimize=ReleaseSafe \
  -Dmodel=/absolute/temporary/model.weights \
  -Dmodel-config=/absolute/temporary/config.zig \
  --prefix /absolute/temporary/application
```

## Edges：边界与限制

- 数据集与评估集仍待用户校准；本轮未修改或用于训练/质量评估。
- 原冻结配置与源码不匹配仍需在后续模型更新中处理，默认冻结模型的运行状态不能用临时模型验证结果代替。
- 当前静态链接方案实测 macOS / Apple M5。Linux 引导已统一使用 `zig cc` / `zig c++`，避免宿主 GCC 的 libstdc++ 与 Zig libc++ ABI 不一致；并补齐线程、数学和动态加载系统库。该分支没有实机验证，Windows、CUDA、Vulkan 工具链亦未验证。
- GPU 设备缺失与驱动故障的错误路径经过代码复核，但本机没有对硬件失效做故障注入。显式 CPU 路径已实测。
- 历史文档保留当时的 zgpu 实现事实；活动源码、构建文件和 README 已无旧后端引用。旧下载缓存不参与当前构建。

4. 默认冻结配置不匹配仍保留保护；Linux ABI 风险通过统一编译器处理但尚未实机验证，没有把本机通过夸大为全部平台、全部模型可用。
