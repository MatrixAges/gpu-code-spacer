# ggml 训练后端迁移执行记录

## Intent：最终目标

将模型训练从 Zig 手写梯度与 Adam 迁移到 ggml 批量计算、自动微分和 `ggml-opt` 优化器，保留现有模型与数据管线的语义。本次交付是训练实现可用性，不是新的代码留白模型。

用户明确补充：数据集和评估集尚未校准，使用临时文件检查可用性。补充要求后未再使用真实训练或评估集。

## Data：可用证据

### 原实现与迁移边界

- 原来的正式训练由 `tools/train.zig` 逐样本执行 `Model.accumulateGradientScaled`，再用手写 Adam 更新；zgpu 仅参与推理。
- 当前源码模型为特征 v6、192→64→3、12,547 个参数。README 中历史训练结果的 v4 数字不代表本轮训练结构。
- 模型仍为两层全连接加 ReLU，初始化、语言/文件采样、类别权重、学习率、batch=64、验证选模、早停与 `.weights` 协议保持。
- `--init` 保持只加载权重、重新初始化优化器状态的原有行为，不宣称恢复训练检查点中的动量。

### 数学与内存核验

1. W1/W2 在上传和下载时显式转置，原 `.weights` 文件和推理读取方式不变。
2. 损失为 `sum(class_weight[label] × CE) / 64`，没有改成除以类别权重之和。
3. 上游融合交叉熵的反向实现使用 `softmax - labels`，假定每条标签的和为 1；因此不能直接传入加权 one-hot。本实现使用 `logaddexp(a,b) = a + softplus(b-a)` 累积 log-sum-exp，再构建加权损失图，避免指数溢出，由 ggml 求导。
4. AdamW 设置 β1=0.9、β2=0.999、epsilon=1e-8、weight_decay=0，保持原 Adam 超参数。
5. 探针需要读取更新前的梯度。固定版本的纯 GRAD 初始化路径会触发上游断言；使用受支持的两次梯度累积周期，只执行第一批并读取累积梯度，再补偿周期的缩放。不修改上游源码。该上下文仅用于一次梯度检查。
6. ggml-opt 会复制静态图，临时节点的数据地址不能直接当作结果读取。参考 logits 写入调用者持有的张量，再读取该张量。
7. 优化器回调持有参数地址，Trainer 必须原位初始化；现有调用者均遵守。释放顺序与初始化失败清理经过只读复核。

上游依据：[训练接口](https://github.com/ggml-org/ggml/blob/7840aaba1989c6deeefede1d77d5aaf8f52b947e/include/ggml-opt.h)、[优化器实现](https://github.com/ggml-org/ggml/blob/7840aaba1989c6deeefede1d77d5aaf8f52b947e/src/ggml-opt.cpp)、[CPU 损失实现](https://github.com/ggml-org/ggml/blob/7840aaba1989c6deeefede1d77d5aaf8f52b947e/src/ggml-cpu/ops.cpp)。

## Edges：边界与限制

- 用户补充要求前，运行过一次旧实现的短训练以了解现有行为。该次输出已移到上述临时目录的 `artifacts/before-clarification-baseline.*`，排除在本次验收、选模与质量论据之外。没有修改训练集、评估集或已发布模型。
- 不运行真实数据的完整训练，不做选模/发布，不利用未校准评估集调参。
- ggml 动态库通过宿主 CMake 和本机优化构建；当前训练封装不是交叉编译方案，训练程序依赖 `.deps/ggml-install`。
- 默认引导在 macOS 包含 Metal，其他平台默认 CPU；CUDA/Vulkan 等需单独配置上游 CMake。Windows DLL 部署未实现或验证。
- CPU 与 GPU 的算子实现和浮点舍入不同，不保证训练结果逐位一致。日志报告主后端，GPU 模式不宣称所有算子均在 GPU 执行。
- 推理应用依然内嵌既有模型，不链接 ggml，不引入运行时旁置模型。

## Answer：交付与自我复核

已交付固定依赖入口、共享 ggml 训练模块、正式训练迁移、现有探针迁移、原生权重兼容、复现说明与验证记录。执行计划中的架构图和数据流图仍适用。

自我复核结论：

1. 最初把问题描述为“zgpu 训练”会误导改动边界，代码证据表明实际需要替换的是 Zig 手写训练；最终改动遵循这个边界。
2. 不把 ggml/GPU 等同于必然更快。当前短运行支持 CPU 默认选项，尚无足够证据作长期训练加速结论。
3. 没有继续保留正式训练的手写梯度兜底，也没有只迁移表层接口。梯度与优化器由 ggml 执行，既有 probe 同样使用该模块。
4. 本次验证独立于待校准的真实数据，但无法回答代码留白质量或泛化是否提高；这些结论仍需用户校准后另行评估。
